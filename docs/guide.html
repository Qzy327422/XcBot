使用指南

从零把 XcBot 跑起来：安装依赖、连接 NapCat、配置模型与 Agent 权限。这里的命令与配置项和实际项目保持一致。

目录 安装 连接 NapCat 配置模型 Agent 与权限 WebUI 常用命令 故障排查

安装

准备 Python 3.12 或更高版本，然后安装依赖：

python -m pip install --upgrade pip
pip install -r requirements.txt
可选依赖：使用 MCP 时需要 pip install mcp，未安装则自动跳过相关功能。

连接 NapCat

XcBot 通过 OneBot 11 协议与 NapCatQQ 通信。推荐把 NapCat 与 XcBot 部署在同一台机器，用 127.0.0.1 连接最稳定。

1. 在 NapCat 开启 WebSocket 服务

打开 NapCat WebUI（默认 http://localhost:6099），进入「网络配置 → 添加 WebSocket 服务器」，设置监听地址与端口。

配置项建议值说明
Host0.0.0.0 或 127.0.0.1容器部署用 0.0.0.0，同机裸装可用 127.0.0.1
Port如 3001必须与 XcBot 连接端口一致
Token自定义设置后 XcBot 需填写相同 Token

2. 在 XcBot 填写连接信息

进入 WebUI 的「连接」页，填写与 NapCat 一致的地址、端口和访问 Token：

连接地址：127.0.0.1
连接端口：3001
访问 Token：与 NapCat 设置的值相同（未设可留空）
连接被重置？先确认端口、路径与 Token 完全一致。若 NapCat 开启了 Token 校验而 XcBot 未填写，握手可能在 TCP 阶段被服务端主动关闭。

配置模型

在 WebUI 的「提供商」页填写兼容 OpenAI 格式的接口，可配置多个并设置轮换顺序：

Base URL: https://api.deepseek.com/v1
模型:     deepseek-chat
API Key:  sk-你的真实Key

随后在 QQ 中 @ 机器人或发送 /帮助 验证是否正常回复。

Agent 与权限

开启 Agent 后，模型会根据任务自主决定是否调用工具，并支持多轮串联执行。工具权限分两档：

权限档位可用能力
所有人查询类、仅作用于当前对话的操作
仅管理员群管理、文件读写、代码执行、MCP

每个会话拥有独立工作区，文件读写默认落在 data/agent_workspace/群号或QQ号/，群与私聊之间互不可见。

安全提示：文件读写与代码执行属于高权限操作，请只对可信管理员开放。

WebUI

默认地址 http://127.0.0.1:7891/，集中管理配置与可观测数据：

页面用途
欢迎运行状态、连接状态
数据统计消息数、模型调用、Token 排名
Agent工具开关、权限、搜索源、MCP
追踪提示词、工具调用明细、Token 用量
聊天室网页内直接与 AI 对话
实时日志完整运行日志
部署在公网时：务必在 WebUI 设置「访问 Token」，否则任何能访问该端口的人都能读到你的 API Key。

常用命令

命令前缀为 /。群里需要 @ 机器人、说出触发词或使用 / 前缀才会触发回复。

/帮助        查看命令列表
/reset       重置当前会话记忆
/停止        中断正在执行的 Agent 工具
/model       查看或切换模型
/重载插件    热重载 plugins 目录

故障排查

机器人完全不回复

检查 NapCat 是否在线、WebSocket 端口是否与 XcBot 一致、Token 是否匹配，并查看 WebUI 实时日志中的连接状态。

联网搜索没有结果

未配置 Tavily / 博查 Key 时会回落到免费搜索源；若仍失败，检查服务器网络能否访问外网。

Agent 不调用工具

确认「Agent」页已开启对应工具，且当前用户具备所需权限档位。
