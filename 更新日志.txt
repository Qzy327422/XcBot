v3.6

思考模型

- [思考模型] 新增思维链处理。支持独立字段（reasoning_content / reasoning）与内嵌标签（<think>、<thinking>、<thought>，含只有开标签或只有闭标签的残缺形态）两种形态；流式输出下标签被切碎也能跨分片正确拼接。剥离点设在模型响应出口，工具循环、关键词检查、历史落盘、分段发送等下游路径拿到的都是纯正文；图片转述与上下文压缩摘要两处旁路出口同样补齐，此前它们直接取 content，思维链会随转述结果回填进主对话、或长期留在压缩历史里污染后续请求。思维链一律不进对话历史、不参与分段发送、不发给 QQ 用户，从根上避免思维链里的"作为AI""角色扮演"等词误触发模型切换关键词、以及思维链被当正文切成多条消息发出。
- [思考模型] 边界情形处理：失败重试时每次尝试开始即重置，多个模型的思维链不再首尾相接拼成一团；工具链复用分支走非流式整理时不与流式已推送的内容重复计入；流式中断、超时或异常时也放出缓冲区中被扣住的尾部内容，此前仅正常结束才处理、末尾十余字符会静默丢失；只有开标签时仅当 <think> 出现在开头附近才视为被截断的思考，避免正文中正常提及该标签导致后续内容被整段吞掉；字段与标签内容互相包含时只保留较完整的一份。

提供商与代理

- [提供商] 提供商页面新增 HTTP 代理输入框，位于 Base URL 右侧。填写后该提供商的全部请求（Bot 模型对话、上下文压缩摘要、图片转述、知识库嵌入、检测模型、WebUI 聊天室）都走此代理；留空为直连，不会回退到全局 HTTP 代理。仅支持 http / https 代理，格式错误在保存时拦截并提示。代理按提供商精确下发，不按 Base URL 反查，同一 Base URL 的多个提供商可各配各的代理；改动代理后不再复用旧连接。
- [提供商] 修复模型调用实际不走任何代理的问题。此前 Bot 的模型请求经 openai SDK 发出，构造客户端时未传入代理配置，全局 HTTP 代理对其无效；现由轮换结果随附各提供商的代理。同时修复留空时仍可能走系统环境代理的问题：openai SDK 在未注入 http_client 时自建的 httpx 客户端默认 trust_env=True，会读取 HTTP_PROXY / HTTPS_PROXY，现改为始终注入显式 trust_env=False 的客户端，保证「留空即直连」。注意该设置同时不再读取 SSL_CERT_FILE / REQUESTS_CA_BUNDLE。
- [提供商] 每个模型新增「思考等级」与「上下文窗口」设置，收在模型行的 ⚙ 按钮里，折起时以小字显示已改动的项。思考等级可选 默认 / 关闭 / 最小 / 低 / 中 / 高，选「默认」时不发送该参数，跟随模型自身行为，不替用户开高档多花思考 token。
- [提供商] 上下文窗口支持自动获取：检测模型时从 /v1/models 响应里读取窗口字段（兼容 context_length、max_model_len、max_context_length、OpenRouter 的 top_provider 等多种键名），自动填入尚未设置窗口的模型。填 0 表示沿用全局 max_context_tokens。
- [提供商] 模型配了上下文窗口时，历史裁剪按该模型的窗口计算并保留 12% 余量给系统提示词与本轮回复；切换到未配置窗口的模型会还原为全局设置，不会沿用上一个模型的值。该逻辑在基类上下文路径（群聊总结等）同样生效，此前只在主对话生效；留余量后至少为 1，避免填写极小值时因结果为 0 被当作「不限制」而彻底关闭裁剪。
- [WebUI] 修正全局 HTTP 代理的字段说明。该代理实际只作用于 GitHub 更新检查、插件市场与 Agent 联网（搜索、抓网页），原说明中的"影响模型调用"与实际行为不符；模型调用请在提供商页面单独配置。全局代理本身的行为未改动。
- [API Key] 同一模型配置多个 Key 时随机选择；移除 API Key 冷却和重置冷却配置，失败后记录错误并在单次请求内按唯一的 Base URL、模型、Key 组合继续轮换，不重复尝试同一组合。尝试身份包含代理地址，修复同一 Base URL、模型、Key 但代理不同的两个提供商中第二个被误判为「已尝试过」而永久跳过的问题。
- [API Key] 轮换结果新增「模型附加参数」字典承载思考等级、上下文窗口等按模型的可选项，后续新增此类配置不再需要加宽元组。

Agent

- [Agent] 修复工具执行成功后模型整理失败直接返回降级错误的问题；保留已完成的工具链，切换下一个模型或 Key 时只重新整理，不重复执行工具；命中回复切换关键词时也按轮换继续尝试。副作用工具的执行状态会写入本轮上下文，切换模型后不会重复执行。
- [Agent] 回复切换关键词只检查经过敏感词过滤、分段清理后的最终发送文本，不再检查工具结果、进度消息或其他中间过程内容。关键词检查与实际发送统一走同一个 build_final_send_parts：敏感词替换在分段之前，检查到的文本与发出的文本完全一致，不会因两处规则分叉而漏检。WebUI 聊天室的回复也补上了敏感词过滤，此前只做了分段清理。

WebUI 聊天室

- [WebUI 聊天室] 支持不同会话并发生成，同一会话仍按顺序串行；所有临时状态（思考中、流式内容、错误、输入草稿、附件、停止标志）按会话 ID 隔离，此前为共用。生成中的会话禁止删除、重命名和切换模型，会话列表显示生成状态；这三项操作增加后端生成中校验，直接调用接口不再能绕过前端拦截（删除正在生成的会话此前会被后台收尾重新写回）。
- [WebUI 聊天室] 修复切换或新建会话会错误停止原会话 Agent，并把预设中断文案"好，那我先停下。"写入原会话的问题；切换后原会话继续后台生成，主动停止只影响指定会话。
- [WebUI 聊天室] 修复生成中途点终止后已输出内容被丢弃、只留下"好，那我先停下。"的问题。点终止后界面立即停止并把已流出的内容就地定稿为该条回复；服务端侧累计流式片段，中断时用它补全最终回复再写入会话，刷新后内容仍在。服务端推送失败不再中断生成，异常路径也会尽量保存已产出内容。
- [WebUI 聊天室] 思考过程以可折叠区域显示在回复上方，默认收起并显示字数，流式生成时实时更新（独立节流，不重绘整个消息列表）。存入会话时截断至 8000 字并计入会话体积预算，此前作为独立字段不参与裁剪计算、会话文件会显著超出上限持续增长。折叠状态改用消息时间戳与 request_id 作为标识，此前用消息数组下标，服务端裁剪旧消息或插入进度消息后下标平移会错位到其他消息上。点终止时已产生的思考过程会与正文一并保留。
- [WebUI 聊天室] 模型下拉现在列出提供商配置里的全部模型，未勾选的模型也可手动选用并标注「·未轮换」。此前只读取轮换列表，导致未勾选的模型在聊天室无法选择；勾选的含义仍是「是否参与自动轮换」，聊天室内的失败切换也只使用已勾选模型作为备选。
- [WebUI 聊天室] 修复进入聊天室时输入框首帧被压扁和页面闪动的问题；固定输入区按钮列宽，在布局完成后显示聊天室，并避免轮询重复重建完整聊天 DOM。
- [WebUI 聊天室] 修复切换会话时异步附件读取完成后附件丢失或串到其他会话的问题；附件始终写回开始选择时所属的会话。

人格与配置热更新

- [人格] 人格设定页面支持新增、编辑、重命名、删除和切换人格预设；增加默认人格、私聊人格、群聊人格三个独立选择，WebUI 聊天室使用私聊人格，无效配置自动回退默认人格。
- [人格] 私聊人格、群聊人格新增「跟随默认」选项并作为默认值。此前二者会被强制写成具体预设 id，导致只改「默认人格」时私聊与群聊仍停留在旧预设；选择跟随后改默认人格即三处同时生效。
- [人格] 修复点击左侧预设列表会连带改掉「默认人格」的问题。左侧列表现在只切换编辑目标，不影响任何生效选择；当前生效的预设在列表中标注"·默认"，编辑区标题显示正在编辑的预设名。
- [人格] 统一空人格预设的处理：选中的预设内容为空时明确报错，不再静默回退到 personality_prompt、内置兜底提示词或其它人设；WebUI 聊天室此前把提示文案当作系统提示词交给模型（模型会照着该句回答），现与 QQ 侧一致。
- [人格] 修复「默认人格」内容为空、私聊/群聊各指向其他预设时，保存配置后已有会话人设不刷新的问题。热更新原先用派生字段 personality_prompt 当守卫，而该字段只跟随默认人格，上述配置下它是空串，整段刷新被跳过，必须重启才生效；现直接交给 _get_system_prompt 判断三级优先级。
- [配置热更新] 人设刷新与上下文上限刷新拆成两个 try。此前共用一个，人格预设为空时 _get_system_prompt 抛出的异常会连带让 max_rounds、max_messages、自动压缩阈值一并不更新——改上下文上限却不生效且无任何提示。现失败时打印原因并保留原人设，不再静默 pass。

知识库

- [知识库] 嵌入请求此前无代理支持，现跟随所属提供商的 HTTP 代理配置。
- [知识库] 向量索引失败回退全文检索时改写入独立的 warning 列，不再占用 error 列。此前降级成功的文档因 error 非空会被显示成失败；文档列表现区分错误（红）与降级提示（黄），并显示当前检索模式。
- [知识库] 增加文档上传、索引中的前端状态提示与索引完成/失败日志，避免上传期间无反馈；修复索引失败后页面不刷新失败状态、旧全文/向量片段残留及片段数未归零的问题。
- [知识库] 索引失败时删除磁盘上的原始文件。documents 行仍保留以显示失败原因，但原文没有留存价值：没有独立的「重新索引」入口，重试必然重新上传并重写文件，检索也只读 chunks 表。此前反复索引失败的大文件会一直占用磁盘，直到手动删除文档才清理。
- [知识库] 修复同一文档并发上传时后一次的成功结果被前一次的失败收尾抹掉的问题。第一次索引很慢（大 PDF 或向量模式下批量嵌入）超过 10 分钟去重窗口后，用户重传会真的重新建索引；此前两次收尾都只检查「文档行还存在」，不检查「这行是否仍属于本次尝试」，于是先完成的那次写好索引后，慢的那次走失败分支把 chunks 删空、状态改为 failed、磁盘原文也一并删除——界面显示索引失败，实际刚刚成功过一次，两次上传全部作废。现在登记时记下本次尝试的时间戳作为凭据，收尾前比对：已被后来的上传接管则完全撒手，不写不删也不上抛异常，直接返回当前文档状态。无并发时的普通索引失败行为不变，仍会报错、置 failed 并清理原文。

WebUI 登录

- [WebUI 登录] 登录页外观与主界面对齐。此前登录页写死一套青蓝配色与四层光晕纹理，主界面按主题预设换色、用的是六层 accent 光晕，两边看着像两个程序。现在登录页共用同一套 CSS 变量与背景规则，七套主题预设逐色一致，浅色/深色两种模式下背景已做逐像素比对；同时关掉登录页多出来的一圈内描边（主界面本就关着），并去掉写死的 bg2/bg3 层次。
- [WebUI 登录] 登录页会显示用户设置的自定义背景图与模糊度，有图时登录卡片自动压暗以保证文字可读。图不由后端下发：登录页没有 Token，要取配置或背景图就得开一个匿名可访问的接口，等于在登录前多一个数据出口。改为主界面登录后把外观（预设、模糊度、背景图缩放后的 data URL）缓存进浏览器本地存储，登录页只读本地缓存，不发起任何未鉴权请求。背景图缩到 1280 宽再转码，避免原图几 MB 直接撑爆存储配额把缓存写坏；缓存值只接受 data: 与 http(s): 两种形态，其余一律忽略，防止被拼进 CSS url() 造成注入。没有缓存时退回内置渐变色，不影响登录。
- [WebUI 登录] 登录按钮改用与主界面「保存设置」相同的样式：accent→accent2 渐变、文字色跟随主题变量、字重一致，浅色模式下渐变掺白。此前按钮写死深色文字，浅色模式下「登录」二字不随主题变色。
- [WebUI 登录] 登录页补齐浏览器保存密码所需的信息。此前 Token 输入框没有 name、表单没有 method，登录又是 preventDefault + fetch 校验 + location.href 跳转，浏览器的「密码用对了要不要保存」启发式只在表单真的提交并发生导航时触发，这条路永远走不到，因此从不弹保存提示。现 Token 框补 name="password" 与 autocomplete="current-password"，表单声明 method="post"，并在校验通过后显式调用一次凭据管理 API 登记凭据（条目名固定为 webui，只是密码管理器里的显示名，不参与任何校验）。界面上仍然只有一个 Token 输入框：加一个永远填 webui、不参与校验的账号框对识别有帮助，但那个框在界面上突兀且没有实际作用，权衡后不加。
- [WebUI 登录] 首次设置访问 Token 成功后也会触发保存密码提示。此前只有登录页那条路径主动登记凭据，首次设置走的是另一个接口，设完密码不弹提示、用户还得自己记住刚生成的随机串。登记时机放在弹窗关闭之后，免得提示气泡被弹层挡住。
- [WebUI 登录] 凭据管理 API 只在安全上下文可用。用 http 加公网 IP 或域名访问时它不存在（实测 window.isSecureContext=false、PasswordCredential 未定义），代码走静默跳过分支，登录与 Token 写入均不受影响，只是那种情况下能否弹保存提示交由浏览器自身判断。想稳定保存请用 localhost 访问或给 WebUI 套 HTTPS。从旧版本升级上来的用户无需任何改动：登录仍是把 Token 放进 X-WebUI-Token 请求头的一次 GET，请求体为空、不含任何账号字段，服务端也只比对 Token，配置文件不需要迁移。
- [WebUI 登录] 表单固定 POST 而不留空 method，避免禁用 JS 时按 GET 提交把 Token 以 ?password= 落进地址栏与浏览器历史；同时给 /auth/login 补上 POST 处理，禁用 JS 时回到登录页而不是 404。
- [WebUI 登录] 移除访问 Token「至少 8 个字符」的硬限制，改为登录失败冷却。前端首次设置弹窗与后端接口两处限制一起去掉——此前后端已放开、前端还拦着，导致首次设置被要求 8 位、之后在设置页改成 1 位却能存下。长度不该由程序替用户定，但短 Token 必须有速率限制兜住：同一来源连续输错 5 次即锁定 30 秒，锁定期内即使 Token 正确也拒绝（猜对就放过等于限流形同虚设），错误提示带剩余可试次数与解锁倒计时，锁到期自动解除、无需重启。5 次 / 30 秒约合每天 1.4 万次尝试，对稍有随机性的 Token 不构成威胁，而输错一次的正常用户也不会被罚站太久。距上次失败超过 15 分钟自动清零，避免零散输错被判为暴力破解。限流只作用于登录探测接口，其余接口偶发 401（比如刚改过 Token）不会把人锁在门外。归组键只用 TCP 对端地址、不读 X-Forwarded-For——那个头客户端可任意伪造，读了等于把限流开关交给攻击者。计数表有条目上限，防止大范围扫描撑爆内存。
- [WebUI 登录] 输入错误时的抖动收敛：原来是 ±4px、linear、抖两轮，晃动过于剧烈；改为单轮 ±2px、缓动衰减，并补 prefers-reduced-motion 兜底。登录卡片本身带垂直位移定位，抖动关键帧里必须把该位移一起写上，否则动画期间卡片会瞬间跳到垂直居中再弹回。

WebUI 移动端

- [WebUI 移动端] 窄屏（≤980px）侧栏改为抽屉。此前移动端只是把两列栅格收成一列，整块导航堆在内容上方，进任何页面都要先划过全部导航项才能看到正文；现在侧栏脱离文档流浮在内容之上，顶栏左侧新增汉堡按钮开合，带半透明遮罩，点导航项、点遮罩、按 Esc 均收起，抽屉打开时锁正文滚动。窗口从窄屏放宽回桌面时清除抽屉状态，桌面布局不受影响。
- [WebUI 移动端] 抽屉的脱流、滚动与底色都按液态玻璃规则的同等具体度改写：液态玻璃外观把侧栏、顶栏统一声明为 position:relative（且带 !important，具体度高于普通类选择器，!important 并不能越过具体度），否则侧栏仍留在栅格里、带着位移占满第一行，把正文整块顶到首屏之外——窄屏下页面只剩背景图；顶栏也会跟着正文滚走、汉堡按钮划出视口。抽屉浮空时补回不透明底色（原先移动端与液态玻璃两处规则都把侧栏刷成透明，堆叠布局下合理，浮层下会直接透出正文），并压下会盖住遮罩的插件上传悬浮按钮。
- [WebUI 移动端] 顶栏改为「汉堡 + 标题」一行、工具条独占第二行且横向可滑，五个按钮不再挤成两行，「保存设置」始终可达；标题与概览数值字号收窄，「11小时 28 分钟」「0.6% / 88.1 MB」不再断在中间。

日志与连接

- [日志] 修复多条日志挤在同一行、后一条不换行的问题。print(x) 会拆成 write(x) 与 write("\n") 两次调用，日志捕获层原先逐次透传，多线程下两次之间会插进别的线程的输出（主程序打启动横幅、Agent 调度器同时打自己的启动日志时必然发生），于是控制台出现「=== 启动中 ===[AgentTask] 调度器已启动」这种两条粘在一起的行；单独那次换行还会在内存缓冲里多存一条空消息，日志页因此每隔一行就是空白。现改为攒到换行才整行发出，一行只调一次底层写入，并且每个线程各攒自己的半行——只加锁不按线程隔离的话，两条正文照样会拼进同一行。\r 也视为行结束，避免进度式输出把后续内容粘上去；程序退出前把没有换行的尾部内容冲出去，不再静默丢弃。
- [连接] 精简断线重连日志。原来每轮重连输出「尝试启动机器人」「连接断开，等待 N 秒后重连」「分隔线」等多行，断连频繁时会把真正的错误刷掉；现在重连只输出一行黄色警告「⚠️ 连接断开，N 秒后重连（第 N 次尝试）」，首次连接单独一行提示。
- [连接] 屏蔽 Hyper 库每轮重连都输出的「🔴 *CRIT 重试次数达到最大值(5)，退出」。该行描述的是 Hyper 内部重试用完，外层仍会继续重连，并非致命错误，但其中的 CRIT 字样会被日志页标红、掩盖真实报错。

调试与追踪

- [调试] 调试页面新增「重启程序」，会先保存记忆与状态、拉起新进程再退出旧进程，重启完成后页面自动刷新。修复该路径实际不保存记忆的问题：它以 os._exit 退出、不触发 atexit，原先注册的收尾回调只释放目录锁；现统一走 save_state_before_restart，与配置热切换重启保存同样的记忆、总结记录、压缩统计并停止调度器。
- [追踪] 追踪详情新增"思考过程"区块，列表页对有思维链的记录显示字数标记。
- [追踪] 追踪列表与详情加载时显示进度条与骨架占位，记录较多时不再长时间空白干等；刷新已有列表时进度条显示在顶部，不再把已显示的内容替换成"正在加载"。修复进度条实际不显示的问题（列表指纹未包含加载状态，自动刷新路径因指纹未变而跳过重绘）。后台每 5 秒的轮询不再触发进度条，只有首次进入与手动刷新才显示。
