v2.4
娱乐功能插件化 / 对话追踪 / HTTP 发消息接口 / 多开支持：

- [插件] 天气、生图、QQ资料查询 拆分为外部插件
  三个娱乐功能从 main.py 移出，改为 plugins/ 下的独立插件：
    plugins/weather/         /天气 [城市]
    plugins/image_search/    /生图 [搜索词]
    plugins/check_account/   /开 [QQ号]
  main.py 从 7204 行减到约 6730 行，主程序聚焦 AI 对话等核心能力。
  三个功能开关（weather / image_generation / check_account）保留在
  WebUI 功能配置页，插件启动时自行读取，行为与原来一致。
  注意：这三个功能现在受「外部插件加载」开关支配，该开关默认值
  已从关闭改为开启，升级后功能不会消失。

- [插件] /开 现在私聊也能用
  原实现只在群聊分支调用，但私聊帮助菜单里却列了这条命令。
  插件版同时支持群聊与私聊，修复了这个不一致。

- [插件] 插件帮助说明自动进入 /帮助 菜单
  插件定义 HELP_MESSAGE 后，内容会追加到 /帮助 的「🔌 插件命令」区块。
  没有插件时该区块不出现，菜单末尾不留空行。

- [插件] 插件日志自动带 [插件名] 前缀
  插件通过注入的 log 打日志，输出形如 [HTTP][weather] geo 北京，
  排查时能立刻看出是哪个插件产生的日志。

- [插件] 插件可声明所需的主程序版本
  主程序在执行插件代码前注入 XCBOT_VERSION，插件在模块顶层校验，
  版本过低时抛异常；失败原因会显示在 WebUI 插件页的失败列表里。
  版本比较使用数字元组，避免字符串比较把 v2.10 判定为小于 v2.4。

- [插件] 插件上下文新增注入项
  filter_sensitive_content（敏感词过滤）、is_feature_enabled（读功能开关）、
  version_name（主程序版本）、ws_url（已拼好的 OneBot 地址）、log（带名日志）。
  不注入 config 对象，避免插件读到 LLM API Key。

- [插件] 命令类插件不再受 AI 对话开关约束
  group_chat / private_chat 的语义是「是否触发 AI 对话」，
  但旧实现在插件执行入口就全局拦截，导致关掉群聊 AI 回复后
  /天气 之类的命令插件也一起失效。现改为只约束 Any 类插件。

- [插件] 修复插件重载导致的模块泄漏
  load_plugins 每次用新标识注册模块却从不清理旧的，
  而 WebUI 每次保存配置都会触发重载，长期运行会累积无法回收的
  模块对象及其全局状态。现在重建前会先清理上一轮注册的模块。

- [插件] 修复第三方插件在私聊可能报缺参
  开发指南示例把 group_id 写为必需参数，但私聊上下文未提供该键，
  照抄示例的插件在私聊会报「缺少参数 group_id」。
  现私聊上下文显式提供 group_id = None。

- [追踪] WebUI 新增「追踪」页
  记录最近 24 小时每次 AI 对话的完整链路，点开可查看：
    · 消息发送链路（用户消息 → 模型回复 → 实际分段数与 message_id）
    · 模型调用链路（每次尝试的模型、耗时、失败原因分类，含重试切换过程）
    · 当次实际发送给模型的系统提示词全文
    · 单条 Token 统计（输入 / 输出 / 缓存命中 / 总计，均取接口真实返回值）
    · 上下文历史（可展开，含每条原文）
  记录开关在追踪页内，默认关闭；修改后需点「保存设置」生效。

- [追踪] 体积控制
  上下文历史、系统提示词、用户消息、模型回复共用一个哈希去重池，
  同一段话在多条记录里只存一份（多轮对话实测节省约 59%）。
  24 小时滚动窗口 + 最多 300 条 + 去重池 600 万字符三重上限，
  实测每天 3000 条对话时文件约 3MB。

- [追踪] 落盘移到后台线程
  避免在事件循环线程上做同步 fsync：旧做法每条对话都会阻塞
  170~300 毫秒，期间所有群的消息和心跳都在等待。

- [接口] 新增 HTTP 发消息接口 POST /api/send
  外部程序或插件可通过 WebUI 端口向 QQ 推送消息，复用 WebUI 访问 Token。
  支持纯文本和 OneBot 消息段数组，共 13 种消息段
  （text/image/at/reply/face/record/video/location/contact/json/dice/rps/music）。
  安全边界：必须配置非空 access_token；拒绝 file:// 与本地路径等来源；
  请求体单独限制 4MB；图片支持 base64://（解码后最大 3MB）。
  可在功能配置页「外部接口」卡片中随时启停，改动无需重启。

- [调试] 调试页新增出站自检
  一键给机器人自己的 QQ 发一条私聊消息，用来验证 OneBot 出站链路是否通畅。
  目标固定为机器人自身，不受 HTTP 发消息开关限制，也无法用来给他人发消息。

- [配置] 入群欢迎语可自定义
  功能配置页新增「入群欢迎」开关与欢迎语编辑框，
  支持 {bot_name} {user_nickname} {user_id} {group_id} 四个占位符。
  文案里的其他花括号（例如 JSON 片段）原样保留，不会导致报错。
  头像与 @ 新成员由程序固定附加。关闭开关后不再查询用户资料。
  顺带修复：原实现在图片发送失败时会丢弃自定义文案退回硬编码欢迎语。

- [多开] 单实例锁改为按目录判定
  旧实现 Linux 固定使用 /tmp/my_bot.lock，整台机器只能运行一个实例；
  Windows 则锁在工作目录而非项目目录。现锁文件位于项目目录内，
  同一目录仍然只能跑一个实例，复制成多份目录即可各跑一个。
  多开时需各自使用不同的 Connection.port 与 WebUI.port。
  锁被占用时会提示占用者 PID；崩溃残留的锁文件不会挡住下次启动。

- [自检] 所有 Python 文件与三个插件编译通过；app.js 语法检查通过；
  项目审计脚本 67 项全部通过。
  说明：本版新增功能均未在真实 QQ 环境端到端验证。

命令匹配改造 / 群聊误触发修复 / 计费保护：

- [命令] 全部命令改为精确匹配，不再使用子串
  原实现大量使用 `关键词 in order` 子串匹配，导致 @机器人 / 名字触发 / 概率触发
  等无前缀路径下，日常闲聊会被误判成命令（例如「我压缩状态不好」会回压缩统计、
  「清除记忆吧」管理员说出来会真的清空群记忆、「关于这件事我想说」会回版本号）。
  新增三个匹配工具函数 match_command（完全一致）、match_command_prefix（关键词+空格）、
  command_argument（取参数），所有命令统一改造：
    · 无参数命令（压缩状态、立即压缩、关于、大头照、token统计、感知 等 15 个）
      改为 order 必须完全等于关键词
    · 带参数命令（天气、生图、开、自动压缩、总结、数据看板 等 7 个）
      改为 order 等于关键词或以「关键词+空格」开头，空格防止「开」命中「开始吧」
    · 管理命令（名言、注销、重启、禁用插件、启用插件 等 8 个）改为 startswith 前缀匹配
    · 自动压缩参数解析：从正则全量捞数字改为按空格切分取位置参数，
      同时修复原有「自动压缩 开启 40条就压缩」这类输入行为不可预测的问题
    · 总结命令：数字只从「关键词」之后取，不再从整条消息里捞，
      修复 /看看20群的总结 会被误判为总结 20 条的问题
  @bot 路径不受影响（main.py 有自动改写机制：@bot 压缩状态 会被拼成 /压缩状态，
  走有前缀的路径，order 正常赋值）。

- [命令] 修复三个隐藏分支遮挡 bug
  「全部压缩状态」因含「压缩状态」被前面的分支先吃掉，永远走不到自己的判断；
  「重置token统计」同理被「token统计」吃掉。精确匹配后自动修复。
  「总结」和「数据看板」同理修复。

- [命令] 插件外加 user_message 前缀保护
  审计发现 weather 和 image_search 两个插件在私聊纯文本和 @触发等路径下，
  也会被子串匹配误触发（私聊说「天气真好」会把「真好」当城市名查询）。
  改为精确匹配，三个插件行为统一。

- [接口] base64 图片校验放过合法空白
  validate=True 会拒绝换行和空格，而从文件或表单读出的 base64 常带换行。
  现改为先剥空白再校验，同时回传剥离后的值，避免把换行透传给 OneBot。
  长度上限也基于剥离后长度，避免大量换行让 4MB 上限实际放行更少数据。

- [接口] 私聊 context 注入 group_id
  插件开发指南的示例把 group_id 写为必需参数，但私聊上下文未提供该键，
  照抄示例的第三方插件在私聊会直接报缺参。已在三处私聊 context 补上 group_id = None。

- [修复] load_plugins 模块泄漏
  每次重载都用新 uuid 注册模块但从不清理旧的，而 WebUI 每保存一次配置都触发
  重载。长期运行会累积无法回收的模块对象。现在重建前会清理上一轮注册的模块。

- [自检] 各项改动均通过 75 项命令匹配测试 + 67 项审计。
  说明：本版新增功能均未在真实 QQ 环境端到端验证。
