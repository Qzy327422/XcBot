v3.2

- [Agent] 精简工具指南，全英文一行，与人格提示词分离
  build_agent_guide() 只返回固定工具规则（英文，一行），不再夹杂当前时间、
  场景、用户等级等随会话变化的信息。环境/工作目录信息在调用处单独追加，
  避免破坏 system prompt 缓存命中。参考 AstrBot TOOL_CALL_PROMPT 风格。

- [Agent] 新增「显示当前时间」开关
  WebUI Agent 页新增开关，默认关闭。开启后每次 Agent 对话在用户消息末尾
  追加 <system_reminder>Current time: ...</system_reminder> 标签，贴在
  用户消息上而非 system prompt 中，不影响缓存。

- [Agent] Follow-Up 消息注入（仿 AstrBot）
  Agent 执行途中用户可发送补充指令改变策略。如 AI 正在用 ffmpeg 转图片，
  用户发"使用python"，AI 下一轮会看到 SYSTEM NOTICE 并切换方案。
  实现：全局活跃会话注册表，消息入口处拦截重定向到 follow-up 队列，
  在 tool result 回灌时合并为 SYSTEM NOTICE 注入 LLM 上下文。

- [追踪] Follow-Up 插话全链路记录（AstrBot 只在日志打一行，不记内容也不记去向）
  追踪详情页的工具链路里，插话卡片紧跟在对应轮次末尾显示，能看出
  「AI 第 1 轮用 ffmpeg 失败 → 用户插话说用 python → 第 2 轮改用 python」。
  记录三种去向，页面用颜色区分：
  1. 已注入（挂在某个工具结果后）—— 记下挂在哪个工具后面。
  2. 已注入（追加一轮对话）—— 模型没调工具就想收尾、但队列里还有插话的场景。
  3. 未送达（循环已结束才发现）—— 橙色标注，避免让人误以为 AI 收到了却没理。
  列表页加 💬 插话 N 标签，一眼看出哪些对话被中途干预过。
  顺带修了个原有缺陷：之前每个工具的结果都会各带一份重复通知，
  同一轮 3 个并发工具就有 3 份。现在整轮结束后只挂一份。

- [修复] v3.2 隐性 Bug 专项排查与修复
  1. [Follow-Up] 修复模型未发起工具调用（纯自然语言回复）时 Follow-Up 消息被静默丢弃的问题。现会自动触发补充轮次。
  2. [Follow-Up] 修复 Follow-Up 指令未写入持久化历史导致问答上下文断层的问题。
  3. [显示当前时间] 修复多模态消息追加时间戳时产生多个散落 text 块导致的 API 400 格式校验错误。
  4. [Agent] 修复系统提示词追加工具指南时对 messages[0] 为 system 角色的强假设漏洞。
  5. [Agent] 修复所有 API 渠道失败、返回只读工具降级结果时不写入对话历史，
     导致下一轮模型不知道自己上一句说过什么的问题。
  6. [Agent] /reset 现在会先中断该会话正在跑的工具循环。原先长任务跑完后的
     存盘会把刚清掉的历史写回来，用户看到「已清除记忆」下次对话记忆却还在。

- [重构] 追踪存储彻底重写为固定条数环形缓冲（学 AstrBot 的轻量化设计）
  过去有三套并行的体积控制机制：24 小时滚动窗口、条数上限、去重池字节预算。
  维护后两者需要频繁全量扫描（每写一条都要算池子总字数、每淘汰一条都要扫全部
  记录的引用），是低配机上的 CPU 大头。现在只剩一个维度：
  1. 去掉 24 小时窗口。想看多久前的记录只由条数决定，不再按时间裁剪。
  2. 去掉去重池与逐字计算。正文（系统提示词/用户消息/回复/历史/工具参数与结果）
     直接内联存在记录里，不再做内容哈希、不再维护引用计数、不再做孤儿回收。
  3. records 换成 deque(maxlen)，满了自动挤掉最旧的，写入从 O(记录数) 降到 O(1)。
     实测极限体量（每条含 30 段历史 + 40 次工具调用）写入 0.15ms/条。
  4. 条数上限默认 100，可在 WebUI 调整（1~1000）。旧的 ai_trace.json（v2 带
     去重池格式）加载时自动迁移成内联格式，不会丢历史。
  5. 顺带收紧单条记录体积：历史条目 60 -> 30 条、单条历史正文 4000 -> 1500 字、
     工具调用明细 80 -> 40 条。取消去重后历史是最容易膨胀的部分，而排查时
     看历史只需知道大概说了什么。

- [WebUI] 功能配置页新增「系统设置」区域
  1. 日志保留天数（默认 7 天，1~365）：data/webui 下超出天数的 runtime-*.log
     自动删除。按文件名里的日期判断而不是 mtime（拷贝备份会打乱 mtime），
     进程内每小时检查一次，保存配置时立即执行一次。
  2. 追踪保存条数（默认 100，1~1000）：改完立即生效，无需重启。调小时多余的
     旧记录当场丢掉。

- [性能] 低配机器优化
  1. [WebUI] 日志读取改为从文件末尾按块回读，不再 read_text() 把整个日志文件
     读进内存再丢掉绝大部分。跑一天的日志有几十 MB，原实现每次刷新都全量读。
  2. [WebUI] 统计页改为增量读取。原先每 60 秒重扫 12000 行日志、跑三万多次
     正则匹配；现在记住上次读到的字节偏移，只解析新增的那几行，并对每行先做
     一次廉价的 [API] 子串判断跳过无关行。实测 89ms -> 0.5ms（172 倍）。
     文件被轮转/清空、末尾半行（正在写入）、累加器超 6 小时过期都有兜底。
  3. [WebUI] 日志默认返回条数 300 -> 100，内存日志缓冲 2000 -> 800 行。
  4. [Agent] overflow 目录清理加 10 分钟防抖，并改用 os.scandir 复用 stat 缓存。
     原先每次超长工具结果落盘都要全量 listdir + 逐个 getmtime，慢盘上很贵。
  5. [Token 统计] 落盘节流 5 秒 -> 60 秒，且不再写缩进（indent=None），
     文件体积和写入量都降到原来的一半以下。
  6. [追踪] 落盘节流 5 秒 -> 30 秒，详情页读取改用 copy.deepcopy
     （原先是 json.dumps + json.loads 双向序列化）。
